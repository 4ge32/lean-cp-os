# 小さな OS を動かしながら学ぶ

Lean CP OS は、「次にどの仕事を動かすか」を Lean で実装し、証明と実行テストで確かめるプロジェクトです。この本では、3 つのタスクを動かす小さな模型から始め、設定可能なタスク制御、C の生成、QEMU 上の実行へ進みます。

**最初は OS や Lean の予備知識がなくても大丈夫です。** 第1章でタスクを起動し、何が起こるかを見てから、その動きを説明する概念とコードを学びます。最後には、変更すべき場所を探し、証明・テスト・説明を一緒に更新できることを目指します。

[第1章を始める →](01-first-run.md)

## 学ぶ道筋

| 段階 | 手を動かすこと | 分かること |
|---|---|---|
| 1〜4章 | 3タスクの例を実行し、状態とコードを追う | スケジューリング、AUTOSAR CP における OS の位置、必要な Lean の構文、リポジトリの配置 |
| 5〜7章 | 証明を読み、設定を変え、QEMU の実行を調べる | 不変条件、起動要求と待ち順、モデルと実際のタスク切り替えの関係 |
| 8〜10章 | 一つの変更を検証と説明まで通す | 仕様から実装・証明・テストへの対応、検証履歴の読み方、保守の手順 |

各章には「試す」「仕組みを理解する」「少し変える」「確かめる」の流れがあります。演習の答えは折りたたんであるので、まず自分で予想してから開いてください。コード例はリポジトリの `examples/book/` に置き、この本に読み込んでいます。同じファイルを CI でも実行します。

## この本で扱う OS の範囲

現在の動作基準は **OSEK OS 2.2.3 の基本タスク制御**です。AUTOSAR Classic Platform の全体像から OS の役割を学び、実装を読むときは現在の対応範囲に沿って進みます。AUTOSAR CP OS R25-11 は将来の照合先であり、仕様への適合を証明済みという意味ではありません。

固定3タスクの教材を **M0**、タスク数・優先度・起動上限を変えられるものを **一般モデル**と呼びます。さらに QEMU 用には容量制限のある **Scalar アダプター**があります。この3つは役割が異なります。

| 層 | 主なファイル | 学習する章 |
|---|---|---|
| M0 の小さな模型 | `LeanCpOs/Model.lean`、`LeanCpOs/Proofs.lean` | 1〜5章 |
| 設定可能な一般モデル | `LeanCpOs/Task/Model.lean`、`Proofs.lean`、`Semantics.lean` | 5・6・8章 |
| C と機械上の実行 | `LeanCpOs/Task/Scalar.lean`、`c/`、`target/aarch64/` | 7章 |

Lean の定理が保証するのは、その定義と前提の下での性質です。C への変換、アセンブリー、CPU までの形式的な対応証明は現在の範囲に含まれません。そこで、モデルの証明と、独立した期待値との比較、QEMU 実行を組み合わせて確かめます。

## 必要なもの

実行手順は Linux x86_64 を前提に、Git、Python 3、GCC、curl、tar と zstd を使います。Lean はリポジトリ指定の **4.19.0** を準備します。QEMU が必要になるのは第7章からです。コマンドは特記のない限りリポジトリのルートで実行してください。

ブラウザーで本文を読むだけならインストールは不要です。ターミナルに不慣れな場合も、第1章のコマンドと期待結果を一つずつ照合できます。

## 使い分ける

- 初めて読むときは、[第1章](01-first-run.md)から順に進みます。
- 実装の場所を探すときは、[リポジトリの地図](04-repository.md)を開きます。
- 変更作業をするときは、[第8章](08-change.md)と[コマンド集](reference/commands.md)を使います。
- 用語や操作を調べるときは、[用語集](reference/glossary.md)と[API 一覧](reference/api.md)を引きます。
- 実行結果を確認するときは、[検証結果の読み方](09-evidence.md)から[検証履歴](verification.md)へ進みます。

本文の説明はリポジトリの `main` と一緒に更新します。特定の過去コミットについて何が確認されたかは、コミットごとの検証レポートを参照してください。
